# Audit — 2026-10-19

Scope: whole repo (`github.com/tsonubin/mdx-file-manager`), audited as product and codebase. Single commit (`fa9a246 first commit`), ~2.5k LOC TypeScript.

## What it is, and for whom

**MDX Asset Manager** is a VS Code extension for content authors who write Markdown/MDX/HTML and store media on S3-compatible storage (AWS S3, Cloudflare R2, any custom S3 endpoint), usually behind a CDN (`publicBaseUrl`).

Core loop:

1. Author drags a local file into the editor (or uses the file-picker command).
2. Extension uploads it to the resolved endpoint profile under a key derived from the document's workspace-relative path (`assets/<dir>/<doc-name>/<file-name>`).
3. A context-aware snippet (Markdown image, `<img>`, `<video>`, `<a>`, or a user template) is inserted at the cursor.
4. A sidebar view ("MDX Assets → File Assets") lists remote assets scoped to the active document, with copy-URL / copy-snippet / delete actions.

Configuration model: endpoint profiles (non-secret) live in VS Code settings; access keys live in `SecretStorage`. Profile resolution order: session override → workspace default → user default → single profile → interactive pick.

Target user is a technical author with their own bucket/CDN — the extension never touches credentials it did not store and does no account management of its own.

## Current state

- **Maturity**: feature-complete MVP. All advertised commands exist and are wired end-to-end. Version 0.1.0, publisher `shay`, one commit, no releases/tags.
- **Tests**: 3 vitest unit suites (`test/`) covering the pure logic (key building, insert rules, profile resolution) + 2 `@vscode/test-electron` integration suites (command registration, profile resolution, drop edits). Reasonable shape; gaps listed below.
- **Build**: plain `tsc`, no bundler. `npm` is the package manager (lockfile present).
- **Missing hygiene**: no LICENSE, no CHANGELOG, no CI, no linter, no `.vscode/launch.json` (so the README's "Press F5" instruction does not work out of the box), no `repository` field in `package.json`.
- **Naming drift**: repo is `mdx-file-manager`, package is `mdx-asset-manager`, UI says "Mdx Assets". Worth converging before publishing.

## Findings

### Bugs

| # | Where | Issue |
|---|-------|-------|
| B1 | `src/assetService.ts` `uploadFiles` | One bad file aborts the whole batch: `fs.stat`/upload errors throw out of the loop. Files already uploaded are orphaned (uploaded, no snippet returned), and the user gets one generic "Upload failed" with no partial result. Dropping a directory hits this path via `EISDIR`. |
| B2 | `src/assets/treeDataProvider.ts` `refresh` | Concurrent refresh race: no stale-response guard. Fast editor switches fire overlapping S3 lists; a slow old response can overwrite the newer state. |
| B3 | `src/commands.ts` `copyAssetSnippet` | Extension derived as `key.split(".").pop()`: for key `assets/v1.2/hero` this yields extension `.2/hero`, corrupting the generated snippet (`basename` slicing in `createInsertContext` then truncates the wrong amount). |
| B4 | `src/upload/s3Uploader.ts` `keyExists` | Only 404/`NotFound` is handled. On S3-compatible stores where `HeadObject` on a missing key returns 403 (common with least-privilege IAM that omits `s3:ListBucket`, and some MinIO configs), the existence check throws and the upload aborts even though `PutObject` would succeed. |
| B5 | `src/config.ts` `normalizeProfiles` | `provider` is passed through unvalidated; a typo'd provider silently degrades to AWS-S3 defaults (region `us-east-1`, no endpoint) instead of erroring. `validateProfile` also never checks `provider`. |
| B6 | `src/profile/commands.ts` `removeProfile` | Removes the profile and the user default but leaves `workspaceDefaultProfile` pointing at the deleted id (harmless at runtime — resolver skips missing ids — but leaves stale config behind). |
| B7 | `src/commands.ts` `copyAssetSnippet`/`deleteAsset` | Handlers are typed for `AssetTreeItem` but `AssetTreeItem.command` passes a bare `AssetRecord` (`extractUrl` papers over this with a dual-type check). Works today only because each call site happens to hit the right branch; the mixed argument shape is one refactor away from `undefined` crashes. |

### Security

| # | Severity | Issue |
|---|----------|-------|
| S1 | **High (content injection)** | Generated snippets interpolate the **raw** filename/alt into HTML/Markdown output. A file named `a" onerror="x.png` produces `<img src="…" alt="a" onerror="x" />` in HTML mode and `![a" onerror="x](…)` in Markdown. Filenames routinely arrive from third parties (client assets, downloads), and in MDX these snippets become JSX. Same for `${filename}` inside user templates. |
| S2 | Medium (product policy) | `.svg` is allowed by default; SVG served from a shared CDN origin is a stored-XSS vector. Mitigation is policy (strip/`Content-Disposition`, dedicated asset origin, or dropping SVG from defaults) — product decision, see below. |
| S3 | Low | `validateConnection` writes and deletes a probe object (`__mdx_asset_manager_probe__/…`) in the user's real bucket. If the delete fails, litter; a validation action should not mutate storage by default. |
| S4 | Informational | Good: secrets only in `SecretStorage`; keys go through `sanitizeSegment` (no path traversal in object keys); no logging of credentials; modal confirm before delete. |

### Performance

| # | Issue |
|---|-------|
| P1 | `uploadFile` reads the entire file into memory (`fs.readFile`) — up to `maxUploadSizeMB` (default 100 MB) per file, held until the PUT completes. Should stream. |
| P2 | Every active-editor change triggers a full `ListObjectsV2` round trip (paginated) with no debounce and no caching; tab-switching through a dozen docs fires a dozen listing scans. |
| P3 | `ensureUniqueKey` does a `HeadObject` per candidate key (serial, up to 10 probes). Rare in practice but each collision costs a round trip; the suffix generator (`Math.random`) is fine for dedupe but the whole check-then-put is racy under concurrency. |

### UX

- "Use X as workspace default profile?" is asked after every interactive profile pick until the user answers *Yes*; *No* re-asks next time. Needs a "don't ask again" or an explicit dismissal — product decision.
- Partial upload results are all-or-nothing (B1): silent loss of snippets is the worst current UX bug.
- `editProfile` cannot rename a profile (id and name are not re-prompted) — fine for correctness, surprising for users.
- Tree shows `Failed to load assets: …` inline, which is good; but a transient network blip wipes the previously listed items (keeps view usable? no — `this.assets = []`).
- File-picker insert uses `editBuilder.insert` (no snippet stops) while drag-drop uses `SnippetString`; behavior differs slightly between the two entry points.

### DX

- **README says "Press F5"** but there is no `.vscode/launch.json`/`tasks.json`, so the first-run experience fails immediately.
- `src/test/fixtures/workspace` (created by `runTest.ts`) is not gitignored → untracked noise after an integration run.
- No linter; no CI; `tsconfig.test.json` is referenced by nothing (`vitest` runs TS itself, `tsc -p ./` ignores it) — harmless but dead weight.
- Integration tests hardcode `shay.mdx-asset-manager` (matches `package.json` today; brittle if the publisher id changes).
- No `package.json` `repository`/`license` fields (marketplace requires a license).

### Docs

- README covers features/settings/commands well, but misses: profile resolution order (session → workspace → user → single), the key layout convention (`assets/<dir>/<doc>/<file>`), credential storage model, R2 setup detail (endpoint vs accountId), troubleshooting (403 on upload, allowed-extensions skips), and any security notes (S1/S2). No screenshots of the sidebar or drop flow. No CHANGELOG.

## Designs for top items

### 1. Escape filenames/alt in generated snippets

All snippet-producing output goes through `buildInsertSnippet`/`renderTemplate` in `src/insert/patternEngine.ts`. Fix at that single boundary: escape `${filename}`/`${alt}` (and `${basename}`) for the target context before interpolation — HTML-escape `& < > "` for HTML output and template output; escape `` [ ] ( ) `` and backslashes for Markdown link/alt text. URLs are already safe (key segments pass `sanitizeSegment`; `publicBaseUrl` is validated to `http(s)://…`). User templates are trusted-ish (user-authored) but interpolations still get escaped since they may be embedded in any context; document that raw `${key}` remains unescaped. Regression test: filename with quotes/parens produces inert output in HTML and Markdown modes.

### 2. Per-file upload isolation + partial results + cancellation

`AssetService.uploadFiles` becomes batch-shaped: wrap each file (stat → validate → unique key → PUT) in its own try/catch; skip-and-collect failures instead of throwing. Result type grows to `{ uploaded: UploadResult[]; failures: { file: string; reason: string }[] }`. Callers (file picker, drop provider) insert snippets for `uploaded` and show one summary notification ("Uploaded 3, failed 2 — <reasons>") instead of swallowing everything. Plumb `vscode.CancellationToken` from the drop provider (it already receives one) and a picker-side cancellation (progress cancel button) into the loop; on cancel, stop starting new files and report what completed. Directories/undecodable files fail only themselves. Regression test at the batch boundary: one failing file among three still yields two snippets and one failure entry.

### 3. Tree refresh: stale-response guard + debounce

`AssetTreeDataProvider.refresh` gets a monotonically increasing generation; only the latest generation may write `assets`/`statusMessage` and fire the emitter (results of superseded calls are discarded). `extension.ts` debounces `onDidChangeActiveTextEditor`/config-change triggers (~200 ms trailing) so rapid tab switching coalesces into one listing. On listing failure, keep the last known items and only change the status message (no more wipe-on-blip). Pure race logic can be unit-tested if extracted; otherwise verify by smoke (switch editors rapidly against a slow fake).

### 4. Stream uploads

`S3Uploader.uploadFile` swaps `fs.readFile` for `fs.createReadStream` as the `Body` of `PutObjectCommand` (SDK supports stream bodies in Node; sets `ContentLength` from the `stat` already taken by the caller). Memory becomes O(1) per upload regardless of `maxUploadSizeMB`. Behavior unchanged otherwise; verify with a large-file smoke upload to a local S3-compatible stub or by integration test if available.

### 5. Existence-check resilience

`keyExists` returns `boolean | "unknown"`: 404/`NotFound` → false; 403/`AccessDenied`/`Forbidden` → "unknown" (cannot verify without `s3:ListBucket`); anything else still throws. `ensureUniqueKey` on "unknown" stops probing and returns a key with a timestamp+random suffix immediately (collision-safe without verification). Also cap probes (already 10) and generate the suffix from `crypto.randomBytes` instead of `Math.random`. Regression test: simulated 403 → upload path proceeds with a suffixed key rather than throwing.

### 6. Extension derivation fix

In `commands.ts` `copyAssetSnippet`, derive the extension from the key's final segment via `path.extname` (mirroring `buildObjectKey`), not `key.split(".").pop()`. One-line fix plus a regression test on a dotted-directory key.

### 7. Provider validation

`validateProfile` rejects unknown `provider` values ("must be one of aws-s3, cloudflare-r2, custom-s3"); `normalizeProfiles` keeps the profile but unknown providers then fail the shared usability check in `AssetService.validateProfileUsability` at upload time (which should reuse `validateProfile` instead of duplicating a subset — small consolidation).

### 8. DX baseline

Add `.vscode/launch.json` (extension host, `outFiles: out/**/*.js`, `preLaunchTask: npm: watch`) and `.vscode/tasks.json` (npm watch background task) so F5 works as documented; add `src/test/fixtures/` to `.gitignore`; README dev section gets an accurate "F5 requires no extra setup" note plus a troubleshooting line for the integration-test VS Code download. No toolchain change.

## Decisions only Shay can make

1. **SVG/content-type policy (S2)**: keep `.svg` allowed (status quo), drop it from defaults, or set `Content-Disposition`/`X-Content-Type-Options` metadata on uploads — depends on whether the CDN origin is shared with the app.
2. **Re-upload semantics**: today re-uploading `hero.png` for the same document creates `hero-abc123.png` (never overwrites). Overwrite-if-same-name is friendlier for iterative asset replacement; unique-suffix is safer against clobbering. Pick one; current behavior matches the README's "auto-unique conflict handling".
3. **Connection validation mutating probe (S3)**: keep the write-probe (verifies PUT permission), make it opt-in, or validate read-only.
4. **"Set as workspace default?" prompt**: add "Don't ask again", auto-set, or keep asking.
5. **Naming + legal + release**: converge repo/package/display naming; choose a LICENSE (marketplace blocker); marketplace publisher and versioning policy; CHANGELOG ownership.
6. **Lint + CI toolchain** (eslint vs biome; GH Actions) — introduces dependencies/dev-workflow changes.
7. **Credential source policy**: `S3Uploader` accepts missing credentials and falls back to the ambient AWS chain (env/profile) — keep as a feature or require explicitly stored credentials.
8. **Profile storage scope**: `addProfile` always writes to global settings even in workspace-centric repos; may want workspace-scope profile storage option.

## Post-audit defaults (implemented 2026-10-19 follow-up)

Items above were taken as safe defaults and implemented; each remains
revisable:

- **#2 Re-upload semantics**: keep never-overwrite (safest against clobbering)
  and make it visible — a notification now names every upload that fell back
  to a suffixed key and states that nothing is overwritten.
- **#3 Connection validation**: the write-probe stays the default
  (`mdxAssetManager.connectionCheck: "write-probe"`) because it is the only
  mode that verifies `s3:PutObject`; a new `"read-only"` mode lists the bucket
  only and never touches objects. Unknown setting values coerce to the
  default.
- **#8 Profile storage scope**: unchanged — commands write profiles to user
  settings and credentials to SecretStorage. The README now documents the
  scope so teams can deliberately commit non-secret profiles in
  `.vscode/settings.json` while credentials stay machine-local.
- **#4 workspace-default prompt**: keep asking by default
  (`mdxAssetManager.promptForWorkspaceDefault: true` — no config mutation
  without an explicit *Yes*) and add a "Don't Ask Again" choice that
  persists `false` in user settings (reversible in the Settings UI).
- **UX findings**: `editProfile` now edits the display name (the id stays
  fixed, so SecretStorage credentials and saved defaults keep working), and
  both insertion entry points insert literal text — snippet syntax (`$…`)
  in URLs or user templates can no longer be reinterpreted by the editor's
  snippet engine.

The remaining items (#1 SVG policy, #5 naming/legal, #6 lint/CI, #7
credential source) stay open.
